# (MVP) 탐색(Discover) 탭: “엑셀처럼 붙여넣기(import)” + 인플루언서 상세 UI 개편
중요: MVP 범위이므로 무분별한 커스텀 컬럼 자동 생성 금지. 아래 “템플릿 규칙”만 허용한다.
또한 파일 업로드 방식 대신, 스프레드시트처럼 셀 클릭/붙여넣기 방식으로 import를 구현한다.
탐색/관리/분석 등 다른 메뉴 구조/라우팅/기능은 변경하지 말고, 이번 작업 범위는 Discover(탐색) 탭 및 인플루언서 상세 패널(드로어)만 수정한다.

────────────────────────────────────────
[1) Import UX: 파일 업로드 금지, 스프레드시트 붙여넣기 방식]
## 1-1. Discover 탭 상단에 버튼 2개 추가
- [데이터 붙여넣기]  (필수)
- [템플릿 복사]      (필수)

## 1-2. “템플릿 복사” 버튼 동작
- 클립보드에 아래 헤더 한 줄(탭 구분 TSV) 복사:
  닉네임\t플랫폼\t플랫폼 계정\t채널 URL\t팔로워\t컨택포인트\t메모\t클라이언트\t세부유형\t컨택여부\t회신 여부\t협업 여부\t콘텐츠 완성본 링크
- 토스트: “붙여넣기 템플릿이 복사되었습니다.”

## 1-3. “데이터 붙여넣기” 버튼 동작(모달)
- 제목: “인플루언서 데이터 붙여넣기”
- 모달 내부에 스프레드시트처럼 보이는 그리드(엑셀 느낌):
  - 셀 클릭 가능
  - 행/열 헤더 고정
  - 엑셀/구글시트에서 복사한 표(행/열 형태)를 그대로 Ctrl+V로 붙여넣으면 그리드에 반영
  - TSV/CSV 둘 다 처리 가능(우선 TSV 최적)
- 그리드 아래에 “미리보기 요약”:
  - 총 행 수, 유효 행 수, 스킵 행 수, 에러 행 수
- 버튼:
  - [검증하기]  (필수)
  - [가져오기 실행] (검증 통과 후 활성화)
  - [취소]

※ 구현 팁: 프론트에서 clipboard text를 파싱하여 2D 배열로 렌더링. (file upload 사용 금지)

────────────────────────────────────────
[2) 템플릿 규칙: 커스텀 컬럼 자동 생성 금지]
## 2-1. 허용 컬럼(화이트리스트) — 이 외 컬럼은 “무시” 또는 “경고”만 표시하고 저장하지 않음
다음 컬럼명만 허용(정확히 일치, 공백 포함):
- 닉네임
- 플랫폼
- 플랫폼 계정
- 채널 URL
- 팔로워
- 컨택포인트
- 메모
- 클라이언트
- 세부유형
- 컨택여부
- 회신 여부
- 협업 여부
- 콘텐츠 완성본 링크

## 2-2. 붙여넣기 데이터에 허용되지 않은 컬럼이 있으면:
- “검증하기” 단계에서 경고 배지 표시: “허용되지 않은 컬럼 n개가 제외됩니다”
- 제외될 컬럼명을 리스트로 보여주되, 자동으로 커스텀필드 생성하지 말 것.
- 가져오기 실행 시, 허용 컬럼만 저장.

## 2-3. 타입/값 파싱 규칙(간단)
- 팔로워: 숫자 파싱(쉼표 제거). 실패 시 null 처리 + 해당 행 경고
- 플랫폼: instagram|youtube|tiktok|x|blog|other 로 매핑
  - 한국어 입력(인스타그램/유튜브/틱톡/트위터/X/블로그)도 매핑
  - 매핑 실패 시 other
- 채널 URL: URL 형태가 아니면 경고
- 콘텐츠 완성본 링크: URL 형태 아니면 그대로 텍스트 저장(링크면 클릭 가능)
- 컨택여부/회신 여부/협업 여부: 값 표준화
  - 허용 값: “Y”, “N”, “진행중”, “보류” (그 외는 경고 후 원문 저장 가능)

────────────────────────────────────────
[3) Import 저장 정책(Upsert / 중복 방지)]
## 3-1. Upsert 키 우선순위
1) (플랫폼 + 플랫폼 계정) 있으면 이 조합으로 upsert
2) 없으면 (플랫폼 + 채널 URL)
3) 없으면 (닉네임 + 플랫폼) (마지막 수단)
4) 전부 없으면 신규 생성

## 3-2. 업데이트 규칙
- 신규 값이 비어있으면 기존 값 유지
- 신규 값이 있으면 덮어쓰기
- “가져오기 결과 리포트”를 모달 하단에 표시:
  - 신규 생성 n, 업데이트 n, 스킵 n, 에러 n
- 에러 행은 저장하지 말고 사유를 표시(예: 필수키 없음)

────────────────────────────────────────
[4) Discover(탐색) 탭 리스트 UI 요구사항(최소)]
- 리스트/테이블 어느 방식이든 OK, 단 최소 컬럼/정보는 표시:
  - 닉네임
  - 플랫폼 배지
  - 플랫폼 계정
  - 팔로워
  - 컨택여부(배지)
  - 회신 여부(배지)
  - 협업 여부(배지)
- 인플루언서 클릭 시 반드시 우측 상세 패널(또는 드로어)이 열려야 함
  - “클릭해도 변화 없음” 절대 금지: selected state + 로딩/토스트 포함

────────────────────────────────────────
[5) 인플루언서 상세 패널 UI 개편(요청 반영)]
## 5-1. 메뉴/섹션 이름 변경
- “기본정보” 탭/섹션: 유지
- “콘텐츠” 탭/섹션 이름을 “협업 내역”으로 변경
- “태그” UI는 제거
- “전화번호” 필드는 “컨택포인트”로 이름 변경(이메일/전화/카톡ID 등 자유 텍스트)

## 5-2. 기본정보(필드 라벨/순서/구성)
기본정보 상단 필드 순서:
1) 닉네임  (기존 ‘이름’을 ‘닉네임’으로 변경)
2) 플랫폼 계정
3) 팔로워

그 아래:
- 플랫폼 (읽기/편집)
- 채널 URL (클릭 가능한 링크)
- 컨택포인트 (기존 전화번호 → 컨택포인트)
- 메모 (기존 위치에서 이동: “기본정보” 섹션의 가장 아래로 배치)

※ ‘메모’는 기본정보 하위 항목으로 이동시키고, 기본정보 내 제일 아래에 위치.

## 5-3. 협업 내역(기존 콘텐츠 탭 대체)
“협업 내역” 탭에 아래 필드를 표시/편집 가능하게 구성:
- 컨택여부
- 회신 여부
- 협업 여부
- 콘텐츠 완성본 링크 (링크면 클릭/새창)
+ (선택) 클라이언트, 세부유형도 함께 노출(이 정보는 운영상 여기서 보는 게 편하면 같이 둬도 됨)

형태:
- 단일 폼(필드 4개) + 저장 버튼
또는
- 라인아이템 테이블 형태(향후 확장 대비) — MVP는 단일 폼으로 충분

────────────────────────────────────────
[6) API/DB(최소 요구)]
- 붙여넣기 검증 API(선택): POST /api/influencers/import/validate
- 실제 import API(필수): POST /api/influencers/import
  - payload: rows(2D) 또는 objects(list) + header list
  - response: created/updated/skipped/errors 상세
- 인플루언서 조회: GET /api/influencers (Discover 리스트)
- 인플루언서 단건 수정: PATCH /api/influencers/:id
- 협업 내역 저장은 influencer 레코드 내 필드로 저장해도 되고, MVP에선 influencer에 직접 필드를 두어도 됨:
  - contactStatus, replyStatus, collabStatus, finalContentUrl

※ “커스텀 컬럼(자동 생성)”은 이번 MVP에서 금지. 오직 위 화이트리스트 컬럼만 저장.

────────────────────────────────────────
[7) 완료 기준(테스트 시나리오)]
1) 사용자가 구글시트/엑셀에서 표를 복사 → [데이터 붙여넣기] 모달에서 그대로 붙여넣기 → 그리드에 행/열 유지되어 표시
2) [검증하기] 누르면 허용 컬럼만 인정되고, 허용되지 않은 컬럼은 경고로 제외됨(자동 커스텀 생성 없음)
3) [가져오기 실행] 후 Discover 리스트에 데이터가 실제로 보임
4) 인플루언서 클릭 시 상세 패널이 열리고, 기본정보/협업 내역 탭이 요청한 라벨/필드/순서대로 보임
5) 컨택여부/회신 여부/협업 여부/콘텐츠 완성본 링크가 “협업 내역” 탭에서 수정되고 저장/새로고침 후 유지됨
