# (MVP) 정산 연계: 인플루언서 DB에 “정산정보” 섹션 추가 + 정산 메뉴 작업큐 재구성 + 엑셀(클립보드) 복사
중요:
- 주민번호는 이번 MVP에서 “텍스트로 저장”하지 않는다(저장 금지). 대신 “서류 업로드(파일)”로만 수집한다.
- 정산 정보(은행/계좌/사업자정보)는 민감정보이므로 접근 권한을 제한한다.
- UI에서 숨기는 것만으로는 부족하며, 서버/API에서 접근 제어를 반드시 적용한다.
- 언어: 사용자 화면 텍스트는 한국어.
- 범위: 기존 캠페인 운영 흐름/탐색/정산 메뉴를 “정산 업무가 실제로 가능하도록” 추가/개선하되,
        기존 다른 메뉴(탐색/관리/분석/커뮤니케이션)의 구조를 불필요하게 뒤엎지 말 것.

────────────────────────────────────────
[0) 권한(최소)]
기존 Role(OWNER/MEMBER/CLIENT)은 유지하되, 정산 관련 화면/데이터 접근은 최소 권한을 둔다.

- FINANCE_ACCESS (정산 메뉴 접근)
- FINANCE_EDIT   (정산 정보/상태 수정, 증빙 업로드, 지급완료 처리)

MVP 권장:
- OWNER: FINANCE_ACCESS + FINANCE_EDIT
- MEMBER: 기본은 FINANCE_ACCESS 없음 (필요하면 특정 사용자에게만 부여)
- CLIENT: 정산 메뉴 접근 불가(기본)

※ 최소 구현: 정산 메뉴와 인플루언서 ‘정산정보’ 섹션은 OWNER만 접근 가능해도 됨.

────────────────────────────────────────
[1) 데이터 설계 원칙: “고정 정산정보” vs “캠페인별 정산업무” 분리]
A) 인플루언서 DB(탐색/프로필)에 저장하는 것: “고정 정산정보”
B) 캠페인-인플루언서 라인아이템에 저장하는 것: “이번 캠페인 정산업무/지급상태”

────────────────────────────────────────
[2) 인플루언서 DB(탐색) 변경: ‘정산정보’ 섹션 추가]
## 2-1. 인플루언서 엔티티에 정산정보 필드 추가(고정 정보)
- settlementType: '사업자' | '프리랜서'
- businessName (사업자등록명) : string|null
- businessRegNo (사업자등록번호) : string|null
- freelancerIdDocFileId (프리랜서 주민번호 대체 서류 업로드) : string|null   # 주민번호 텍스트 저장 금지
- bankName (은행명) : string|null
- accountHolder (예금주명) : string|null
- accountNumber (계좌번호) : string|null
- settlementInfoUpdatedAt
- settlementInfoUpdatedByUserId

※ 주민번호는 절대 텍스트로 저장하지 말고, 파일 업로드로만 수집한다.

## 2-2. 탐색 탭 UI: 인플루언서 상세 패널에 “정산정보” 영역 추가
위치:
- 인플루언서 상세 패널(드로어) 내 탭/섹션으로 추가
- 탭명: “정산정보”
- 접근: FINANCE_ACCESS 이상만 노출(권한 없으면 탭 자체 숨김)

정산정보 폼 구성(필수 항목은 상태에 따라 다름):
A) 구분(라디오)
- 사업자 / 프리랜서

B) 사업자 선택 시:
- 사업자등록명 입력
- 사업자등록번호 입력

C) 프리랜서 선택 시:
- “주민번호 서류 업로드” (파일 첨부)
- 안내 문구: “주민번호는 텍스트로 저장하지 않으며, 서류 업로드로만 수집합니다.”

D) 공통(사업자/프리랜서):
- 은행명
- 예금주명
- 계좌번호

버튼:
- [저장]
저장 시:
- settlementInfoUpdatedAt / settlementInfoUpdatedByUserId 기록
- 변경 로그(audit) 1건 남김(선택)

## 2-3. 정산정보 완비 여부 계산(뷰/배지)
인플루언서마다 settlementInfoCompleteness 를 계산해 배지로 표시:
- 사업자: businessName + businessRegNo + bankName + accountHolder + accountNumber 모두 있으면 “완비”
- 프리랜서: freelancerIdDocFileId + bankName + accountHolder + accountNumber 있으면 “완비”
탐색 리스트/캠페인 운영/정산 메뉴 어디서든 “완비/미비” 배지로 활용 가능.

────────────────────────────────────────
[3) 캠페인 라인아이템(운영) 변경: 지급 트리거/정산 업무 필드]
정산 메뉴 작업큐는 “업로드 완료로 표시된 라인아이템”만 올라온다.

## 3-1. 라인아이템에 필드 추가(캠페인별)
- isUploadCompleted (boolean default false)
- uploadCompletedAt (date|null)
- uploadCompletedByUserId (string|null)

- payoutStatus enum:
  - '정산정보미비'
  - '증빙요청'
  - '증빙수령'
  - '지급대기'
  - '지급완료'
  - '보류'

- payoutAmountSupply (number|null)  # 공급가
- payoutVat (number|null)           # VAT
- payoutTotal (number|null)         # 총액
- payoutMemo (string|null)

- invoiceFileId (string|null)       # 세금계산서/청구서 등 증빙 파일
- invoiceIssuedAt (date|null)       # 발행일(선택)
- payoutDueAt (date|null)           # 지급 예정일(선택)
- paidAt (date|null)
- transferProofFileId (string|null) # 이체확인증(선택)

## 3-2. 업로드 완료 트리거(운영 탭 내)
캠페인 운영 라인아이템(또는 콘텐츠 탭)에서:
- 체크박스: “업로드 완료”
- 체크 시:
  - isUploadCompleted=true, uploadCompletedAt/By 기록
  - 기본적으로 payoutStatus를 다음 중 하나로 자동 설정:
    - 정산정보가 미비하면: '정산정보미비'
    - 정산정보가 완비하면: '지급대기' (또는 '증빙요청'을 기본으로 둘지 선택)
MVP 권장:
- 업로드 완료 체크 시 기본 payoutStatus = '정산정보미비' 또는 '지급대기' 자동 전환
  (정산정보Completeness 기준으로 분기)

- 체크 해제(undo) 가능:
  - 해제 시 uploadCompletedAt/By 초기화, payoutStatus는 이전값 유지 또는 '보류'로(택1)

────────────────────────────────────────
[4) 정산 메뉴 재구성: “작업 큐 + 상세 패널”]
경로: /finance (또는 기존 ‘정산’ 메뉴 경로 유지)
접근: FINANCE_ACCESS 이상만

## 4-1. 정산 메뉴 상단 KPI(간단)
- 지급대기 건수
- 지급대기 총액(합계)
- 정산정보미비 건수
- 보류 건수

## 4-2. 정산 작업 큐 테이블(핵심)
기본 필터:
- isUploadCompleted = true 인 라인아이템만 노출(기본 on)
필터:
- 클라이언트
- 캠페인
- payoutStatus
- 정산정보 완비(완비/미비)

컬럼(추천 최소):
- 클라이언트명
- 캠페인명
- 인플루언서(닉네임/플랫폼)
- 업로드 완료일(uploadCompletedAt)
- 정산정보(완비/미비 배지)
- 지급 상태(payoutStatus 배지)
- 지급 총액(payoutTotal)
- 지급 예정일(payoutDueAt)
- [상세] (행 클릭)
- (선택) [입금완료 처리] 빠른 버튼

정렬 우선:
- payoutStatus = '정산정보미비' / '지급대기' 우선
- uploadCompletedAt 오래된 순(지연 처리)

## 4-3. 우측 상세 패널(행 클릭)
섹션 A: 기본정보
- 클라이언트/캠페인/인플루언서
- 업로드 완료 체크 정보(누가/언제)

섹션 B: 정산정보(인플루언서 고정 정보 불러오기)
- settlementType, 사업자등록명/번호(사업자), 프리랜서 서류 파일(프리랜서)
- 은행명/예금주/계좌번호
- “정산정보 수정” 버튼(누르면 인플루언서 정산정보 탭으로 이동 또는 인라인 편집)

섹션 C: 지급 금액(캠페인별)
- 공급가 / VAT / 총액 입력
- 메모 입력
- (선택) 자동 계산 토글: 총액=공급가+VAT

섹션 D: 증빙
- 세금계산서/청구서 파일 업로드(invoiceFileId)
- 발행일(invoiceIssuedAt)
- 이체확인증 업로드(transferProofFileId)

섹션 E: 상태/처리
- payoutStatus 드롭다운 변경
- 지급 예정일(payoutDueAt)
- 버튼:
  - [지급대기로 이동]
  - [입금완료 처리]
    - 클릭 시 paidAt=now, payoutStatus='지급완료'
    - (선택) 이체확인증이 없으면 경고만 띄우고 진행 가능(MVP)
  - [보류]

────────────────────────────────────────
[5) “엑셀 복붙” 기능: 클립보드 TSV 복사(핵심)]
정산 메뉴 테이블에서:
- 다중 선택 체크박스 제공
- 버튼: [입금용 복사] (payoutStatus='지급대기'인 행만 대상으로 기본 동작)

클립보드에 복사되는 TSV 컬럼(탭 구분, 헤더 포함):
은행명    계좌번호    예금주명    금액(총액)    메모
- 메모 필드 포맷: "{클라이언트명}/{캠페인명}-{인플루언서닉네임}"

옵션:
- “사업자정보 포함” 토글(ON 시 컬럼 추가):
  - 사업자등록명, 사업자등록번호
※ 프리랜서의 주민번호는 텍스트로 저장하지 않으므로 복사 항목에 포함하지 않는다.

복사 완료 토스트:
- “입금용 데이터가 클립보드에 복사되었습니다(TSV). 엑셀에 붙여넣으세요.”

────────────────────────────────────────
[6) 접근제어(필수)]
- 탐색 탭의 ‘정산정보’ 탭/섹션:
  - FINANCE_ACCESS 이상만 노출 및 API 접근 허용
- 정산 메뉴:
  - FINANCE_ACCESS 이상만
- 정산 수정/입금완료 처리:
  - FINANCE_EDIT 이상만

CLIENT 역할은 정산 메뉴 접근 불가(기본).
(향후 확장 제외)

────────────────────────────────────────
[7) 완료 기준(테스트)]
1) 인플루언서 상세에 “정산정보” 탭이 생기고(권한 있는 사용자만),
   사업자/프리랜서에 따라 입력 폼이 다르게 보이며 저장된다.
2) 프리랜서 주민번호는 텍스트로 저장되지 않고, “서류 업로드”로만 수집된다.
3) 캠페인 운영에서 “업로드 완료”로 체크한 라인아이템이 정산 메뉴 작업큐에 나타난다.
4) 정산 메뉴에서 지급금액 입력 및 지급상태 변경이 가능하다.
5) 지급대기 건을 다중 선택 후 [입금용 복사]를 누르면 TSV가 클립보드에 복사되어 엑셀에 그대로 붙는다.
6) [입금완료 처리]를 누르면 지급완료로 바뀌고 완료일이 기록된다.
7) FINANCE 권한 없는 사용자는 정산정보/정산 메뉴 접근이 차단된다(서버 레벨 포함).
