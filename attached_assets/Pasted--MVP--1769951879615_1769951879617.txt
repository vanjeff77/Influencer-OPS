# (MVP) 사용자 및 액세스 + 클라이언트 메뉴 + 클라이언트 스코프 접근제어
중요: 이번 작업은 “사용자 및 액세스”, “클라이언트” 메뉴를 추가하고,
클라이언트 유저가 본인에게 할당된 클라이언트 데이터만 볼 수 있도록 ‘서버/API 레벨’에서 차단하는 것이 핵심이다.
UI에서 메뉴를 숨기는 것만으로 접근제어했다고 간주하지 말 것.
언어: 사용자 화면 텍스트는 한국어.
초기 MVP 제약: 회원가입/초대메일/SSO 없이, 워크스페이스 소유자가 직접 “이메일 + 비밀번호”를 설정해서 계정을 만들어준다.

────────────────────────────────────────
[1) 역할(Role) — 3개 고정]
- WORKSPACE_OWNER   (워크스페이스 소유자)
- WORKSPACE_MEMBER  (워크스페이스 실무자)
- CLIENT            (클라이언트)

역할별 기본 권한(단순화, MVP):
- OWNER: 전 메뉴 접근 + 사용자/클라이언트 관리 가능
- MEMBER: 업무 메뉴 접근(탐색/캠페인/그룹/분석/커뮤니케이션 등 기존 메뉴), 단 사용자/클라이언트 관리는 불가
- CLIENT: 제한된 메뉴만 접근(아래 5번 참고) + 본인에게 할당된 Client만 접근

────────────────────────────────────────
[2) 클라이언트 스코프(데이터 범위) — 핵심 규칙]
- 모든 캠페인/인플루언서/커뮤니케이션/콘텐츠/트래킹/정산(있다면) 데이터는
  “workspaceId”와 “clientId”로 필터링 가능해야 한다.
- CLIENT 역할 사용자는 server/API에서 반드시:
  - clientId ∈ assignedClientIds 인 데이터만 조회/수정 가능
- MEMBER/OWNER는 기본적으로 workspace 범위 내 전체 접근 가능
(향후 확장은 제외, MVP는 단순 유지)

※ 반드시 API 레벨에서 차단할 것:
- 프론트에서 메뉴를 숨겨도 URL 직접 접근을 막아야 한다.

────────────────────────────────────────
[3) 신규 메뉴: “클라이언트” (OWNER 전용)]
## 3-1. 클라이언트 목록
- 테이블 컬럼: 클라이언트명, 활성 캠페인 수, 할당 사용자 수, 상태(active/inactive)
- CTA: [클라이언트 추가]

## 3-2. 클라이언트 생성/수정
필드:
- 클라이언트명(필수)
- 로고(선택)
- 메모(선택)
- 상태(active/inactive)

## 3-3. 클라이언트별 사용자 할당
클라이언트 상세 화면에서 “할당 사용자” 섹션 제공:
- 사용자 검색/선택 후 추가
- 할당 해제
- CLIENT 역할 유저는 최소 1개 Client에 반드시 할당되어야 함
  (미할당이면 접근 가능한 데이터가 0이 되도록 처리)

────────────────────────────────────────
[4) 신규 메뉴: “사용자 및 액세스” (OWNER 전용)]
초기 MVP 요구사항:
- 워크스페이스 소유자가 “이메일 + 비밀번호”를 직접 설정해서 계정을 만든다.
- 초대메일/회원가입/비밀번호 재설정 메일은 이번 MVP 범위에서 제외한다.

## 4-1. 사용자 목록
- 테이블 컬럼: 이름(선택), 이메일, 역할(OWNER/MEMBER/CLIENT), 할당된 클라이언트 수, 상태(활성/비활성)
- CTA: [사용자 추가]

## 4-2. 사용자 추가(계정 생성)
- 입력: 이메일(필수), 비밀번호(필수), 역할(필수), (CLIENT인 경우) 클라이언트 할당(필수)
- 저장 시:
  - 비밀번호는 평문 저장 금지. 반드시 해시 처리(예: bcrypt).
  - 동일 이메일 중복 생성 금지.
- OWNER만 계정 생성/수정/삭제 가능.

## 4-3. 사용자 수정
- 역할 변경(OWNER ↔ MEMBER ↔ CLIENT)
- 비밀번호 재설정(OWNER가 새 비밀번호 직접 입력 후 저장)
- 활성/비활성 토글(비활성 사용자는 로그인 불가)
- CLIENT 역할이면 “클라이언트 할당” 편집 가능

────────────────────────────────────────
[5) CLIENT 역할 유저의 메뉴/화면 제한(프론트 + 백엔드)]
CLIENT로 로그인 시:
- 좌측 메뉴 노출(최소):
  - 개요(Overview)
  - 캠페인(자기 클라이언트 캠페인만)
  - (선택) 커뮤니케이션/콘텐츠 탭은 캠페인 상세 내에서만 접근 가능
- 숨김:
  - 탐색(Discover)
  - 그룹(Manage)
  - 분석(Analyze)
  - 사용자 및 액세스
  - 클라이언트

추가로, API에서도 CLIENT는 본인 할당 clientId 범위 밖 데이터는 403/404로 차단.

────────────────────────────────────────
[6) 로그인/세션(MVP)]
- 로그인 화면: 이메일 + 비밀번호
- 로그인 성공 시 세션/토큰 발급(쿠키 세션 또는 JWT 중 택1)
- currentUser에 workspaceId, role, assignedClientIds 포함
- 모든 API는 currentUser를 기반으로 접근제어 수행

────────────────────────────────────────
[7) 데이터 모델(개념, MVP)]
- Workspace { id, name, logoUrl? }
- User { id, workspaceId, email, passwordHash, role, isActive, createdAt }
- Client { id, workspaceId, name, logoUrl?, memo?, status }
- ClientUserAssignment { id, clientId, userId }  # 다대다
- Campaign { id, workspaceId, clientId, ... }
(다른 주요 엔티티도 가능한 한 clientId를 가져 스코프 필터링 가능하게 유지)

────────────────────────────────────────
[8) 완료 기준(테스트 시나리오)]
1) OWNER가 “사용자 및 액세스”에서 이메일/비밀번호로 MEMBER/CLIENT 계정을 생성할 수 있다.
2) CLIENT 계정 생성 시 클라이언트 할당이 필수이며, 미할당이면 접근 데이터가 0이다.
3) CLIENT로 로그인하면 메뉴가 제한되고, 본인에게 할당된 클라이언트의 캠페인만 조회된다.
4) URL/API로 다른 클라이언트의 캠페인/데이터에 접근 시 서버에서 차단된다(403 또는 404).
5) 비밀번호는 해시로 저장되고, 평문 저장이 없다.
