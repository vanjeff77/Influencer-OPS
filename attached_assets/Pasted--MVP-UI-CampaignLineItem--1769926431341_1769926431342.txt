캠페인 상세 페이지에 “콘텐츠” 탭을 MVP 범위로 구현해줘. (겉 UI만이 아니라 실제로 저장/수정/조회가 동작해야 함)
기존 구조가 CampaignLineItem(캠페인-인플루언서 단위) 중심이므로, 콘텐츠 데이터는 반드시 라인아이템에 귀속되어야 한다.

────────────────────────────────────────
[목표]
인플루언서 마케팅 캠페인의 콘텐츠 운영을 위해 아래 4가지를 캠페인 단위로 한 화면에서 관리한다:
1) 초안 제공 일정(초안 제공 예정일)
2) 업로드(게시) 일정(게시 예정일)
3) 게시 URL
4) 검수 상태(아래 상태값 고정)

────────────────────────────────────────
[검수 상태(고정 워딩 / enum)]
다음 6단계를 “검수 상태(reviewStatus)”로 사용한다. UI/배지/필터/다운로드에서 동일하게 노출한다.
1. 초안 대기
2. 초안 검토 대기
3. 피드백 전달 완료
4. 수정본 대기
5. 게시 예정
6. 게시 완료

(간단 자동 규칙 - 가능하면 구현)
- 게시 완료: 게시 URL 필수
- 게시 예정: 게시 예정일 필수
- 초안 검토 대기: 초안 링크/파일이 1개 이상 존재하면 자동 전환(또는 버튼으로 전환)
- 초안 대기: 초안 링크/파일이 없으면 기본값

────────────────────────────────────────
[데이터 모델 / DB]
기존 DB에 아래 필드를 추가하거나 별도 테이블(ContentItem)을 만든다.
권장: CampaignLineItem 1개당 콘텐츠 레코드(ContentItem) 1개(또는 콘텐츠가 여러 개면 1:N으로 확장 가능)

ContentItem(권장 컬럼)
- id
- campaignId
- lineItemId (필수, 관계)
- influencerId
- draftDueAt (초안 제공 예정일, nullable)
- publishDueAt (게시 예정일, nullable)
- postUrl (게시 URL, nullable)
- reviewStatus (enum, 기본값: "초안 대기")
- postedAt (실제 게시일, optional)
- memo (optional)
- updatedAt/createdAt

※ 파일/초안 링크 업로드는 이번 범위에선 옵션. 우선 위 4개 필드 + 상태만 확실히 동작하면 MVP 합격.

────────────────────────────────────────
[UI 요구사항: 캠페인 상세 > 콘텐츠 탭]
1) 테이블 기반 UI(필수)
- 행 단위: CampaignLineItem(인플루언서 1명)
- 컬럼(최소):
  - 인플루언서(이름/핸들)
  - 초안 제공 예정일(draftDueAt)
  - 게시 예정일(publishDueAt)
  - 검수 상태(reviewStatus) (드롭다운 변경)
  - 게시 URL(postUrl) (인풋/링크)
  - 저장/수정 액션(자동 저장도 가능)
2) 클릭/편집 동작(필수)
- 인플루언서 행 클릭 시 Drawer(또는 우측 패널) 열기
  - 동일 필드(draftDueAt, publishDueAt, reviewStatus, postUrl, memo) 편집 가능
  - 저장 시 DB 반영 + 토스트(한국어) 노출
3) 필터/정렬(가능하면)
- 상태 필터(6개 상태)
- 게시 예정일 기준 정렬(오름/내림)
4) 완료 판정 UX
- reviewStatus가 “게시 완료”일 때 postUrl이 없으면 저장 불가 + 경고 문구 표시
- reviewStatus가 “게시 예정”일 때 publishDueAt 없으면 경고 문구 표시

────────────────────────────────────────
[API 엔드포인트(필수)]
- GET /api/campaigns/:id/content-items
  - 해당 캠페인의 라인아이템 + 콘텐츠 필드들을 함께 반환(join)
- PATCH /api/content-items/:id
  - draftDueAt, publishDueAt, postUrl, reviewStatus, memo 업데이트
- (콘텐츠 레코드가 없을 때)
  - POST /api/campaigns/:id/content-items/bootstrap
    - 캠페인 라인아이템을 기준으로 ContentItem을 일괄 생성(기본값: 초안 대기)

※ 프론트에서 버튼 클릭/행 편집 시 반드시 위 API를 호출해 DB에 저장되어야 함.
※ “클릭해도 아무 변화 없음” 이슈가 재발하지 않도록, 편집 시 네트워크 요청이 발생하고 UI가 즉시 갱신되게 구현(optimistic update 또는 refetch).

────────────────────────────────────────
[시드 데이터/테스트 시나리오(필수)]
- 캠페인 1개 + 라인아이템 3개를 기준으로 ContentItem을 생성
- 시나리오:
  1) 콘텐츠 탭 진입 → 3명 행이 보임
  2) 1명 행에서 초안 제공 예정일/게시 예정일 입력 → 저장 → 새로고침 후 값 유지
  3) reviewStatus를 “게시 완료”로 변경 → postUrl 없으면 경고
  4) postUrl 입력 후 “게시 완료” 저장 → 성공 토스트 → 새로고침 후 유지

────────────────────────────────────────
[UI 텍스트(한국어 고정)]
- 탭명: “콘텐츠”
- 필드 라벨:
  - “초안 제공 예정일”
  - “게시 예정일”
  - “게시 URL”
  - “검수 상태”
- 상태 배지 텍스트는 enum 워딩 그대로 사용
- 토스트 예:
  - “저장되었습니다.”
  - “저장에 실패했습니다.”
  - “게시 완료 상태에는 게시 URL이 필요합니다.”
  - “게시 예정 상태에는 게시 예정일이 필요합니다.”
