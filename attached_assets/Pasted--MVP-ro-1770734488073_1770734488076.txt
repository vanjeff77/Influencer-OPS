# (MVP) 인플루언서 행별 “상태형(단계형) 프로그레스 바” 구현 프롬프트 (컨택/확정 필수 조건 포함)
목표:
- 인플루언서 선정(리스트) 화면에서 각 인플루언서 행(row)마다
  진행 단계를 한눈에 보여주는 “단계형 프로그레스 바”를 표시한다.
- 프로그레스 바는 ‘표시’만이 아니라, “다음 단계로 전환”하는 컨트롤로 동작한다(Clickable Step Bar).
- 사용자는 항상 “다음 가능한 단계 1개만” 클릭 가능하도록 제한한다.
- 상태 전환 시 필수 입력 조건을 검사하고, 조건 미충족 시 상태 전환을 막고 안내 UX를 제공한다.
- UI 텍스트는 한국어.

────────────────────────────────────────
[1) 단계 정의(고정 순서)]
인플루언서 단계는 아래 순서를 따른다:

선정 → 컨택 → 확정 → 계약 → 초안수신 → 완성본수신 → 업로드완료

내부 상태 enum 예시:
- SELECTED
- CONTACTED
- CONFIRMED
- CONTRACTED
- DRAFT_RECEIVED
- FINAL_RECEIVED
- PUBLISHED

────────────────────────────────────────
[2) 리스트(인플루언서 선정 메뉴) 행 UI 요구]
각 인플루언서 행에 다음 요소를 표시한다:
A) “단계형 프로그레스 바(클릭 가능)” (필수)
B) “현재 단계 텍스트 배지” (권장)

## 2-1. 프로그레스 바 UI 형태(컴팩트)
- 단계 라벨을 짧게 표시:
  선정 / 컨택 / 확정 / 계약 / 초안 / 완성본 / 업로드
- 완료된 단계: 채워진 원(●) 또는 채워진 바
- 현재 단계: 강조된 원(◎) 또는 강조 바
- 미진행 단계: 비활성 원(○) 또는 점선 바

예시(텍스트 개념):
선정 — 컨택 — 확정 — 계약 — 초안 — 완성본 — 업로드
 ●        ●        ◎        ○      ○        ○        ○

## 2-2. 클릭 가능 규칙(중요)
- 사용자는 “다음 가능한 단계 1개만” 클릭할 수 있다.
- 이전 단계로 되돌리기(rollback)는 MVP에서 비활성(추후 옵션).
- 이미 완료된 단계는 클릭 불가(또는 히스토리 보기만).

## 2-3. 현재 단계 배지(권장)
- 프로그레스 바 옆에 현재 단계 배지를 표시:
  예: “🟣 확정”, “🟡 컨택”, “✅ 업로드완료”

────────────────────────────────────────
[3) 상태 전환 로직(필수 조건 검사)]
프로세스:
1) 유저가 프로그레스 바에서 “다음 단계”를 클릭
2) 시스템이 해당 단계의 필수 조건을 검사
3) 조건 충족 → 상태 업데이트 + 타임라인(로그) 기록
4) 조건 미충족 → 상태 변경 차단 + 안내 UX 제공

────────────────────────────────────────
[4) 필수 조건 상세(요구사항 반영)]
## 4-1. 컨택(CONTACTED) 전환 조건
- 시스템은 “컨택 메뉴(커뮤니케이션/이메일)”에서
  해당 캠페인 + 해당 인플루언서에 연결된 이메일 스레드가 있는지 검사한다.

A) 이메일 스레드 내역이 존재하면:
- 즉시 CONTACTED로 상태 변경
- 로그 기록: “컨택 완료(이메일 스레드 존재)”

B) 이메일 스레드 내역이 없으면(스레드 없음 또는 메시지 0건):
- 상태 변경을 바로 하지 말고 확인 모달을 띄운다.
- 모달 문구(정확히):
  “메일에 컨택내역이 없습니다. 컨택으로 기록할까요?”
- 버튼:
  [컨택으로 기록하기] / [취소]
  - “컨택으로 기록하기” 클릭 시:
    - CONTACTED로 상태 변경
    - 로그 기록: “컨택 완료(수동 기록)”
  - 취소 클릭 시: 상태 변경 없음

## 4-2. 확정(CONFIRMED) 전환 조건(강제 입력)
- 확정 처리 전에 반드시 아래 2개 데이터가 입력되어야 한다:
  1) 광고비 (number)
  2) 업로드 예정일 (date)

A) 두 값이 모두 입력되어 있으면:
- CONFIRMED로 상태 변경
- 로그 기록에 광고비/업로드 예정일 포함

B) 하나라도 없으면:
- 상태 변경을 차단하고 강제 안내를 표시한다.
- 안내 문구(정확히):
  “확정 처리 전 광고비와 업로드 일정을 입력해주세요”
- UX:
  - 확인 버튼만 제공(또는 확인 후 자동 이동)
  - 확인 클릭 시 인플루언서 상세(드로어)를 열고
    ‘광고비’ 입력 필드에 자동 포커스한다.
  - 광고비 입력 후 ‘업로드 예정일’로 포커스 이동

────────────────────────────────────────
[5) 데이터 저장(필드)]
인플루언서-캠페인 관계(라인아이템)에 아래 필드를 저장한다:
- progressStatus (enum)
- adCost (광고비, number)  # 확정 조건 필수
- scheduledPublishDate (업로드 예정일, date) # 확정 조건 필수
- communicationThreadId (optional) # 이메일 스레드 연결
- timelineEvents[] (로그) 또는 별도 테이블

────────────────────────────────────────
[6) 로그(타임라인) 기록]
상태 변경 시마다 아래를 기록한다:
- 이전 상태 → 새 상태
- 변경 시간
- 변경 사용자
- 컨택의 경우: 이메일 스레드 존재/수동 기록 여부
- 확정의 경우: 광고비/업로드 예정일 스냅샷

(로그는 상세 드로어에서 “진행 타임라인”으로 볼 수 있게 한다.)

────────────────────────────────────────
[7) 완료 기준(테스트 시나리오)]
1) 리스트에서 각 인플루언서 행에 단계형 프로그레스 바가 보인다.
2) 현재 단계와 완료/미완료 단계가 시각적으로 구분된다.
3) 다음 단계만 클릭 가능하다.
4) 컨택 클릭:
   - 이메일 스레드가 있으면 즉시 컨택 처리된다.
   - 이메일 스레드가 없으면
     “메일에 컨택내역이 없습니다. 컨택으로 기록할까요?”
     모달이 뜨고 확인 시 컨택 처리된다.
5) 확정 클릭:
   - 광고비/업로드 예정일이 모두 있으면 확정 처리된다.
   - 없으면
     “확정 처리 전 광고비와 업로드 일정을 입력해주세요”
     메시지가 뜨고 입력 전까지 확정 처리되지 않는다.
6) 상태 변경은 로그로 누적되고, 상세 드로어의 타임라인에서 확인 가능하다.
