# 목표
기존 SaaS에서 "개요(Overview)" 탭을 실무자가 매일 보는 '컨트롤 타워'로 개선한다.
중요: 다른 메뉴(탐색/캠페인/그룹/이메일센터/정산/트래킹)의 구조나 기능은 변경하지 말고,
Overview 페이지 UI/데이터 집계/클릭 이동만 추가/개선한다.
언어: 사용자 화면의 모든 텍스트(라벨/버튼/메시지)는 한국어.

# 현재 상태
Overview에는 환영 배너, 바로가기 카드(탐색/캠페인/이메일/트래킹), 최근 활동이 존재한다.
하지만 “오늘 해야 할 일”과 “업무 우선순위”가 없어 실무 효용이 낮다.

# 개선 요구사항(Overview 탭 전용)
## A. 상단 "KPI 카드" 영역(액션형)
다음 KPI 카드를 4~6개 보여준다. (필수 5개)
각 카드 클릭 시 해당 페이지로 이동하거나, 해당 페이지로 이동하며 필터 상태가 적용되도록 한다.

필수 KPI 카드:
1) 진행 중 캠페인 수 -> /campaigns (진행중 필터)
2) 응답 대기 인플루언서 수 -> 캠페인 > 커뮤니케이션 관련 화면으로 이동(가능하면 /campaigns/:id?tab=communication + status=미응답)
3) 확인 필요(이슈) 건수 -> /tracking 또는 /campaigns의 이슈/콘텐츠 리스트(가능한 곳으로 이동)
4) 이번 주 업로드 예정 콘텐츠 수 -> 캠페인 상세의 콘텐츠 탭 또는 콘텐츠 리스트로 이동
5) 지급 대기 정산 총액(합계) -> /finance 또는 /settlements (지급대기 필터)

선택 KPI:
- 계약 미완료 건수
- 오늘 마감(초안/피드백/업로드) 건수

KPI 산출은 "mock data"로 시작해도 되지만, 가능한 경우 기존 DB(Prisma)가 있다면 거기서 집계한다.
집계가 불가능한 항목은 0으로 두지 말고 샘플 데이터로 화면이 제대로 보이게 한다.

## B. "오늘의 할 일" 섹션(가장 중요)
Overview의 핵심 섹션으로 "오늘 처리해야 할 일" 리스트를 만든다.
- 우선순위 정렬(높음->낮음)
- 각 아이템은 상태 배지/기한/대상(캠페인명+인플루언서명)/CTA 버튼을 포함
- CTA 클릭 시 해당 캠페인 상세의 해당 탭으로 이동하거나, 이메일센터/정산 등 관련 화면으로 이동

UI는 체크리스트 형태(완료 체크 가능)로 제공한다.
완료 체크는 '사용자 개인' 기준(다른 팀원과 공유되지 않아도 됨)으로 저장된다(로컬스토리지 또는 DB).

## C. "커뮤니케이션 요약" 섹션
최근 48시간 기준:
- 새 답장(수신) n건
- 미응답 n명(최초 발송 후 x일 이상 미응답 기준)
각 리스트 아이템 클릭 시 해당 스레드/캠페인 커뮤니케이션 탭으로 이동.
(현재 커뮤니케이션 기능이 미완성이라면, 더미 스레드 리스트로 UI만 구성)

## D. "콘텐츠 진행 현황" 섹션
상태별 카운트 + 바로가기:
- 초안 대기
- 피드백 대기
- 업로드 예정(D-3 이내)
- 업로드 완료(이번 주)
각 상태 클릭 시 캠페인 콘텐츠 탭 또는 콘텐츠 리스트로 이동.

## E. "리스크 & 알림(확인 필요)" 섹션
다음 유형을 한 곳에 모아 보여준다(최대 10개):
- 트래킹 오류/수집 실패
- 콘텐츠 비공개 감지
- 계약 미완료인데 콘텐츠 진행 중
- 정산 정보 미수집인데 지급일 임박
각 항목은 "무엇이 문제인지 1줄" + "바로가기" 제공

## F. UI 구성(레이아웃)
- 상단: 큰 배너(현재 유지 가능) + KPI 카드 row
- 중단: 2열 레이아웃
  - 좌: 오늘의 할 일(길게)
  - 우: 커뮤니케이션 요약 + 콘텐츠 진행 현황(카드 형태)
- 하단: 리스크&알림 + 최근 활동(기존 유지 가능)

## G. 네비게이션/링크
각 카드/리스트 항목 클릭 시 실제 라우트로 이동해야 하며,
현재 해당 라우트가 없으면 최소한 existing page로 이동이라도 동작하게 한다.
(예: /campaigns, /email-center, /tracking, /finance)

# 결과물 검증 기준(필수)
1) Overview에서 '오늘의 할 일'에 최소 5개 이상 항목이 보인다(더미 OK)
2) 모든 KPI 카드가 클릭 가능한 링크/버튼이며, 페이지 이동이 된다
3) '오늘의 할 일' 체크 완료가 새로고침해도 유지된다(로컬스토리지 OK)
4) 전체 UI 텍스트가 한국어다
5) 다른 메뉴의 UI/구조는 변경하지 않는다

# 구현 힌트(선택)
- Task 생성은 아래 "Task Rule Engine" 로직에 따라 서버/클라이언트에서 생성 가능
- 우선 MVP는 더미 데이터로 UI부터 완성 후, 추후 실제 데이터 연동
